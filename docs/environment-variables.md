# Environment Variables

Roadmap step 276. Every real environment variable this project reads, in one
place. This is an INDEX, not the authoritative source — each variable's own
full rationale (why this default, what breaks if it's wrong) lives in
`config.py`'s own inline comments or the `.env*.example` file it came from;
this doc exists so nobody has to open three separate files and read a whole
settings class just to answer "does this app read a `FOO_BAR` variable, and
what does it do." Generated by reading `apps/api/config.py:Settings` in full
(the actual, single source every one of these binds to — no scattered
`os.environ.get()` calls anywhere else in this codebase) rather than
re-derived from memory.

Real files, in order of how you'd actually touch them:

- [`apps/api/.env.example`](../apps/api/.env.example) — copy to `apps/api/.env` for local dev.
- [`apps/web/.env.example`](../apps/web/.env.example) — copy to `apps/web/.env.local` for local dev.
- [`.env.prod.example`](../.env.prod.example) — copy to `.env.prod` for a real deployment (`docs/self-hosted-deployment.md`).
- `apps/widget` reads **no environment variables at all** — every real config option is a `data-*` attribute on the embed `<script>` tag instead (`docs/embedding.md`'s own Configuration reference).

## `.env.prod` (repo root, `docker-compose.prod.yml`)

A distinct set of names for the *production reference deployment* specifically
— see [`.env.prod.example`](../.env.prod.example) for the full, current list
(it's kept in that one file rather than duplicated into a table here, since
`docker-compose.prod.yml`'s own `${VAR:?...}` syntax is the actual
authoritative source of what's required, and the two would drift). At a
glance: real Postgres/MinIO credentials, the same `SECRET_KEY`/`JWT_SECRET`/
`MFA_ENCRYPTION_KEY` trio above, and `PUBLIC_API_URL`/`APP_BASE_URL` for the
real public-facing deployment.
